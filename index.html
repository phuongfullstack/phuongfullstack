02 — Work

What I work on

Six areas that cover most of what a .NET application needs between an idea and production.

Backend

ASP.NET Core, EF Core, API design

Minimal APIs, middleware and background services on modern .NET. EF Core against SQL Server and PostgreSQL — migrations, compiled queries, split queries. Versioned contracts with validation and ProblemDetails.

Frontend

Angular first, and whatever the product needs

Angular by default, plus Vue, Svelte and React, wired to .NET APIs with typed clients generated from OpenAPI. WPF where the product is a desktop application.

Cloud & DevOps

Azure and AWS, built and shipped repeatably

Docker multi-stage builds, GitHub Actions and Azure DevOps pipelines, infrastructure described in Terraform, deployed to App Service, Functions or Container Apps.

Performance

The part most people skip

Index and query tuning driven by execution plans, killing N+1 before it reaches production, caching layers that actually invalidate, and numbers from BenchmarkDotNet rather than impressions.

Security

Secure by default

ASP.NET Core Identity, JWT and cookie auth, policy-based authorisation, and defence against XSS, CSRF, SQL injection and IDOR. Secrets in Key Vault, not in configuration files.

Testing

So refactors aren't scary

xUnit and NUnit with Moq for units, integration tests through WebApplicationFactory and Testcontainers against a real database, all wired into CI so a red build blocks the merge.

03 — Approach

How I work

Engineering habits, not personality traits.

  • Measure before optimisingAn execution plan or a benchmark comes before the rewrite. "Feels slow" is a starting point, not a diagnosis.
  • Small changes, green pipelineFocused pull requests with tests that run in CI, so a red build stops a regression instead of a reviewer having to catch it.
  • Boring technology where it countsProven framework features over clever abstractions in the parts of a system that are expensive to get wrong.
  • Write down the whyComments and commit messages explain the reasoning, because the code already explains the what.
  • Secure by defaultParameterise every query, authorise every handler, keep secrets out of configuration — not as a hardening pass at the end.
  • Leave it runnableA README that works from a clean clone, and deployment that survives someone else pressing the button.
