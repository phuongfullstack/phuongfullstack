How I work

Engineering habits, not personality traits.

  • Measure before optimisingAn execution plan or a benchmark comes before the rewrite. "Feels slow" is a starting point, not a diagnosis.
  • Small changes, green pipelineFocused pull requests with tests that run in CI, so a red build stops a regression instead of a reviewer having to catch it.
  • Boring technology where it countsProven framework features over clever abstractions in the parts of a system that are expensive to get wrong.
  • Write down the whyComments and commit messages explain the reasoning, because the code already explains the what.
  • Secure by defaultParameterise every query, authorise every handler, keep secrets in Key Vault — not as a hardening pass at the end.
  • Leave it runnableA README that works from a clean clone, and deployment that survives someone else pressing the button.
